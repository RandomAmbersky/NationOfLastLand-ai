# Todo List - Frontend Improvements

## 🔴 Критические проблемы

1. **Дублирование архитектуры**
   - `game-engine.js` (новая архитектура) и `game-demo.js` (старая) существуют параллельно
   - `index.js` экспортирует оба подхода, создавая путаницу
   - Нет миграционного плана с legacy на новую архитектуру

2. **Отсутствие модульных тестов для новых систем**
   - Нет тестов для `RendererSystem`, `InputSystem`, `SelectionSystem`, `GameStateSystem`
   - Тесты только для устаревшего `game-demo.js`

3. **Смешение ответственности**
   - `RendererSystem` создает сущности (`createEntitySprite`) И синхронизирует их (`_syncEntities`)
   - `GameStateSystem` одновременно управляет состоянием и вызывает WASM функции
   - `EntityService` использует `gameEngine.state.get()` напрямую вместо абстракции

## 🟡 Проблемы архитектуры

4. **StateContainer не является истинным источником истины**
   - `RendererSystem._renderedEntities` хранит дублирующую информацию
   - `SelectionIndicator` работает напрямую с Pixi контейнерами вместо через систему

5. **Отсутствие централизованного coordinate transformer**
   - `RendererSystem` создает свой `transformer` в `init()`
   - `InputSystem` и `SelectionSystem` дублируют логику преобразования координат

6. **Непоследовательный обмен данными**
   - Системы получают `gameEngine` в конструкторе
   - Нет явного API для взаимодействия между системами

## 🟠 Проблемы кода

7. **Ошибки в `_syncEntities`** (`RendererSystem.js:244`)
   ```javascript
   if (createdCount > 0 || removedCount > 0) {
   }  // Пустой блок - логирование отсутствует
   ```

8. **Утечки памяти**
   - `RendererSystem` удаляет сущности из `_renderedEntities`, но не проверяет, есть ли контейнер
   - `SelectionIndicator` не вызывает `destroy()` у индикаторов при удалении сущностей

9. **Отсутствие обработки ошибок**
   - `initWasm()` вызывается асинхронно, но ошибки не обрабатываются в `GameDemo.initializeGame()`
